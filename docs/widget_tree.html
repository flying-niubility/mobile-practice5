① 为什么是两类 Widget？

页面会变，所以 CounterPage 必须是 StatefulWidget；它只负责“造 State”。真正可变的 _count、_step 住在 _CounterPageState 里。像 CountDisplay、StepSelector、Text、Icon 这种纯按入参渲染、自身不变的部分，一律用 StatelessWidget。

② 点 FAB 之后发生了什么（setState 链路）

FloatingActionButton onPressed → _addStep() → setState(() => _count += _step) → 框架把该 State 标记为 dirty → 下一帧重新执行 build() → 变化的子树被替换，界面随之刷新。

③ Theme.of(context) 的两处取用

一是 Theme.of(context).colorScheme，用主色 colorScheme.primary 画计数文字；二是 Theme.of(context).textTheme，用 displayLarge / titleMedium 定字号。种子色一改，这里全同步。

④ 资源为什么必须重启

图片在 pubspec.yaml 的 flutter.assets 下声明为 assets/images/，代码用 Image.asset 读取并铺作 AppBar 背景。只改 pubspec 不重启，拿不到新资源清单，就会报 “Unable to load asset”。

⑤ 生命周期日志落点

钩子顺序：initState → didChangeDependencies → build（可多次）→ didUpdateWidget → dispose。热重载（r）保留 State、只重跑 build；热重启（R）重置 State，会重新走 initState。
